# iDoris AI Discovery Skill v0.1

> 完整执行细节见 [`../discovery-sop.md`](../discovery-sop.md)。
> 这份 SKILL.md 是**流程骨架**，SOP 是**逐小时的执行手册**。两者一起用。

## 这个 Skill 保证什么

**任何一个 FDE 按它走完，产出的九项交付物格式一致、可横向比较。**
不一致就是 Skill 的 bug，不是人的问题。

这是 iDoris 差异化的载体：市面上有大量 AI 工具，但没有开源的
**AI 采纳方法论**。工具是红海，方法论是空白。

## 五个阶段

```
① 定范围  →  ② 广度采集  →  ③ 量化  →  ④ 收敛  →  ⑤ 交付
   进场前      Day 1         Day 2      Day 3      Day 3 下午
```

### ① 定范围（进场前）

1. 用 `templates/scoping-checklist.md` 判定 3 天还是 5 天。
   **满足 2 条及以上「5 天」判据就报 5 天**；拿不准也报 5 天。
2. 发 `templates/pre-engagement-email.md`，索取五样材料。
3. **硬门槛**：拿不到「至少一个决策层愿意受访」就推迟，不进场。
   没有老板参与的 Discovery 一定会变成一群中层陪你聊天。

### ② 广度采集（Day 1）

按 `interview/owner.md` → `interview/manager.md` 的顺序访谈。
**顺序不可改**：先老板后中层，从战略到执行；
每套问题内部也从宽到窄、从事实到判断，避免先入为主。

每场结束**立刻**补 `02-pain-inventory.md`，不要攒到晚上。

Day 1 结束必须有：engagement log、工作流地图 v0（可以是错的）、痛点清单 ≥10 行。

### ③ 量化（Day 2）

1. `interview/user.md` 访谈一线。
2. **影子观察**：坐旁边看他真做一遍，全程计时。不打断。
   记三个数：单次耗时、切换了几个软件、几步是复制粘贴。
   **复制粘贴的步数是最好的 AI 机会指标**——它意味着信息在系统间靠人搬运。
3. 按 `templates/pain-inventory.md` 的公式算年化工时与成本。
4. 按 `templates/readiness-score.md` 的判据打五维分。

**没有数字的痛点在提案阶段一定会被砍掉。**

### ④ 收敛（Day 3 上午）

1. 三轴打分 → `scripts/score.py` → 矩阵与排序。
2. **Top 3 的挑法不是取分数最高的三个**：
   - 第 1 个：一周内能见效的（建立信心）
   - 第 2 个：价值最大的（证明值得投钱）
   - 第 3 个：战略性但要时间的（引出下一期）
3. 原型，**时间盒 2.5 小时**（5 天版 6 小时）。到点没做出来就降级成
   录屏 + 说明，并在交付物里写明这是模拟不是实物。**不许撒谎说跑通了。**

### ⑤ 交付（Day 3 下午）

交付会讲的顺序**不按文档顺序**：

1. 我们看到了什么（工作流 + 年化工时）← 客户会频频点头，你说的是他们自己的公司
2. 跑原型 ← 信任在这一刻建立
3. Top 3 与矩阵
4. 90 天路线图
5. **主动讲局限**：哪些做不了、哪些不建议做、哪些有风险

第 5 条是分水岭。只讲好处的顾问满街都是。

收尾**不要说「有需要联系我们」**——那等于结束。约一个具体时间点。

## 九项交付物

目录与文件名固定，见 `templates/deliverables-structure.md`。**缺一项不算交付。**

## 三条硬规矩

1. **不带方案进场。** Day 1 就开始想解决方案，你会把自己会的东西硬塞进去。
2. **「建议他们别做」是合法结论。** Readiness ≤10 分就照实写。
   这是可信度的来源，不是失败。
3. **样例与对外材料一律虚构。** 客户的数据、流程、业务逻辑永不进开源仓库。
