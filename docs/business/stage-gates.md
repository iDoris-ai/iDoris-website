# 阶段门检查表

> **缺一项不准进下一阶段。** 打印出来，或复制到每个客户的项目笔记里。
> 版本：v0.1 · 2026-09-05 · 依据 [`playbook-customer-journey.md`](playbook-customer-journey.md)

## 为什么要这个

流程图告诉你**顺序**，检查表告诉你**能不能过**。

一个人身兼三职时，最容易出的错是跳过对自己的质疑——
销售冲动直接变成开发承诺。**逐项打勾是唯一的替代品。**

---

## 门 1 · Lead → Qualified（BD）

- [ ] 属于 ICP：教育 / 旅游服务 / 知识密集 SME
- [ ] 客户能**具体指认**至少一件重复性工作（不是「我们效率有点低」）
- [ ] 确认了谁能拍板预算，且此人知道我们在谈
- [ ] 客户明确表示愿意付费（哪怕便宜）
- [ ] 已记录客户**自己说的**痛点原话，不是我的转述
- [ ] 不符合以上任一条 → 记进 Nurture 或 Dropped，**并写下理由**

## 门 2 · Qualified → DiscoveryScoped（BD → PM）

- [ ] 已判定 3 天还是 5 天（按 `discovery-sop.md` §0.2 的五条判据）
- [ ] 报价单已发出，含**交付物清单**与**验收标准**
- [ ] 价格取值有依据（按 `pricing.md` §2 的九因素）
- [ ] 客户口头接受
- [ ] **BD 已把五样东西交给 PM**：组织情况 / 联系人图谱 / 痛点原话 / 已承诺范围与价格 / 已知红线
- [ ] **⚠️ PM 已书面回执「范围可交付」** ← 一个人时也必须写下来
- [ ] 若 PM 判定不可交付 → **打回改范围，不硬接**

## 门 3 · DiscoveryScoped → DiscoveryRunning（BD → PM）

- [ ] 合同或定金到位（**不是口头承诺**）
- [ ] 进场前邮件已发出，五样材料已索取
- [ ] 组织架构图或团队清单 ✓
- [ ] **⚠️ 至少一位决策层已确认受访时段** ← **硬门槛，拿不到就推迟**
- [ ] 3–5 位受访者名单与时段已排定
- [ ] 日常软件清单 ✓
- [ ] 3 份真实工作文档样例（脱敏）✓
- [ ] 客户一句话的「最浪费时间的是什么」✓

## 门 4 · 进场第一小时（PM）

- [ ] 录音同意已口头取得并**记进 `00-engagement-log.md`**
- [ ] 数据边界已确认：哪些不能看、哪些不能拷贝
- [ ] 交付会时间与参加人已定，**且含决策层**
- [ ] 已当众说过那句话：「如果我们发现你们暂时不需要上 AI，我们会直说」

## 门 5 · Day 1 收尾（PM）

- [ ] `00-engagement-log.md` 含同意记录与数据边界
- [ ] `01-workflow-map.md` v0 已画（**可以是错的，但必须有**）
- [ ] `02-pain-inventory.md` ≥10 行
- [ ] 老板访谈已完成，且是 1 对 1

## 门 6 · Day 2 收尾（PM + Dev）

- [ ] **影子观察已做**，不是只听人说
- [ ] Top 3 候选涉及的痛点有**实测**单次耗时（不是自述）
- [ ] `02-pain-inventory.md` 每行六列齐全，**年化工时已算**
- [ ] 时薪来源已注明（实数或明确标注的假设）
- [ ] `03-readiness-score.md` 五维已打分，每维有判据依据
- [ ] `06-data-privacy.md` 初稿完成
- [ ] `01-workflow-map.md` v1 已被一线确认过

## 门 7 · DiscoveryRunning → DiscoveryDelivered（PM + Dev）

- [ ] 九项交付物**全部存在**（缺一项不算交付）
- [ ] 原型能跑；**若降级为录屏，`prototype/README.md` 已写明这是模拟不是实物**
- [ ] Top 3 的第 1 个是「一周内能见效」的（Effort ≤2）
- [ ] `07-roadmap-90d.md` 的 30/60/90 三段**各有可验收产出**（无「持续优化」这类话）
- [ ] 交付会已当面讲过，且按五步顺序（看到什么 → 原型 → Top3 → 路线图 → **局限**）
- [ ] **已主动讲过至少一件「不建议做」的事**
- [ ] 收尾已约下一个**具体时间点**（不是「有需要联系我们」）

## 门 8 · Proposed → Implementation（BD + PM + Dev）

- [ ] Readiness 分数与所选档次匹配（≤10 不上 L2/L3）
- [ ] **UAT 用例已双方书面确认**
- [ ] **⚠️ Before/After 基线已测** ← 实施前测，事后回忆不算
- [ ] 数据边界与权限约束已交给 Dev
- [ ] **⚠️ Dev 已回执：技术可行性 + 工期 + 待澄清问题清单**
- [ ] 待澄清问题**全部已澄清**（有未澄清就不开工，标 BLOCKED 回给 PM）
- [ ] 自动放行相关的约定已写进合同附件（若涉及 Agent）

## 门 9 · Implementation → Operating（Dev → PM）

- [ ] UAT 用例逐条跑过并通过
- [ ] 管理员手册已交（怎么改配置、怎么看日志、出问题找谁）
- [ ] 用户手册已交（**不含技术术语**）
- [ ] **已知限制清单已主动写出**（不等客户发现）
- [ ] 交接培训已做，管理员能独立操作
- [ ] **⚠️ Before/After 度量已完成并出报告**
- [ ] 验收签字
- [ ] 运维合同已谈（默认跟在实施后面提出，不是事后追加）

## 门 10 · 每月运维（PM）

- [ ] 用量与成本月报已发客户
- [ ] Skill/Agent 是否需要更新已复查
- [ ] 有无新员工需要 onboarding
- [ ] **有无新的高价值流程**（→ Expansion 机会）
- [ ] 模型/API 是否有变更影响现有配置

---

## 用法

1. 每个客户复制一份，放进该客户的项目笔记
2. 门没过就**停在原地**，不要「先往下走，回头补」
3. **打勾的人要写名字和日期**——一个人时也写，这是给三个月后的自己看的
