# iDoris 服务定义

> 四阶段服务各自做什么、几天、交付什么、**什么情况下该卖、什么情况下明确不该卖**。
> 价格见 [`pricing.md`](pricing.md)。版本：v0.1 · 2026-09-05

## 一条总的销售纪律

**「明确不该卖」那几栏比「该卖」重要。**

我们卖的是判断力。一个会说「你们现在还不该做这个」的供应商，
下一次客户会先想到他。只讲好处的顾问满街都是。

---

## 0. AI Readiness Call — 免费

**做什么**：30–60 分钟通话，判断这家组织现在用 AI 有没有戏。

**交付物**：一页纸的机会初判（口头 + 一封跟进邮件）。

**什么情况下该做**：任何一个符合 ICP（教育 / 旅游服务 / 知识密集 SME）的组织。

**什么情况下不该做**：
- 对方只想要免费咨询、明确说没预算 → 礼貌结束，记进 Nurture
- 对方要的是「帮我做个网站/APP」→ 不是我们的生意，转介

> **免费只到这里为止。进场之后一分钟都不免费。**
> 客户说「能不能先免费试试」——答：资格判定通话是免费的，我们先聊 40 分钟。

## 1. Discover — AI Discovery Sprint

**做什么**：进企业 3 或 5 个工作日，找出哪些活最值得让 AI 干，
给一张 90 天路线图和一个当场能跑的原型。

**几天**：3 天或 5 天（判据见 [`discovery-sop.md`](discovery-sop.md) §0.2）

**交付物**（九项，缺一项不算交付）：
1. Current Workflow Map（含耗时表）
2. AI Readiness Score（五维）
3. Pain Point Inventory（**含年化工时与成本**）
4. Top 3 AI Use Cases
5. Impact × Effort × Risk 矩阵
6. **可运行的小 Prototype**
7. Data / Privacy 风险
8. 90-Day Roadmap（30/60/90 三段，每段可验收）
9. Implementation Proposal

**什么情况下该卖**：
- 客户说得出具体的重复性工作
- 有人能拍板预算
- **愿意让至少一位决策层接受访谈**（硬门槛）

**什么情况下明确不该卖**：
- ❌ **拿不到决策层受访** → 推迟，不进场。没有老板参与的 Discovery
  一定会变成一群中层陪你聊天，最后没人拍板
- ❌ 客户已经明确知道要做什么、只想找人实现 → 直接卖 Implementation，
  别为了多收一笔硬塞 Discovery
- ❌ 组织正在重组/换 CEO/大裁员 → 流程本身在变，测出来的东西下个月就过期

---

## 2. Enable — Role-Based AI Enablement

**做什么**：围绕**员工每天真实在做的工作**做实战培训，不是教 Prompt。

**几天**：1–3 天

**交付物**：
1. Role-Based Training Plan（按角色不按工具）
2. 组织自己的例子（**必须来自 Discovery 的发现，不用通用例子**）
3. Prompt / Skill Playbook
4. 工具与模型配置建议
5. 数据处理守则
6. 动手工作坊
7. **可复用 Skill Pack**（交付物是资产，不是 PPT）
8. 训后采纳检查表（2 周后回访用）

**什么情况下该卖**：
- Discovery 做完，发现瓶颈在「人不会用」而不是「没有工具」
- Readiness 的「人员意愿」维度 ≥3 分

**什么情况下明确不该卖**：
- ❌ **没做过 Discovery 就来买培训** → 会变成通用 AI 培训，
  而泰国政府、大学、大厂现在都在免费教这个。**我们竞争不过免费。**
  正确做法：先卖 Discovery，或明确告诉客户去上免费的
- ❌ 「人员意愿」≤2 分（明确抵触、怕被替代）→ 培训解决不了抵触，
  先解决管理层沟通问题
- ❌ 客户要「给全公司 200 人培训」→ 拆开。一次面对一个角色群体才有效

## 3. Implement — Skills / Agents / 集成

三档，按客户的数字化基础选。

### L1 — Skill Pack

**做什么**：把一组常用 AI 能力配好、文档化、给例子。

**典型内容**：文档摘要与抽取、合同对比、翻译改写、报价/提案起草、
演示材料准备、设计辅助、会议转任务、调研综合、营销内容生成。

**交付物**：配置好的 Skill 包 + 文档 + 例子

**工期**：1–2 周

**该卖给**：Readiness 11–17 分的组织。这是绝大多数第一次合作的客户。

### L2 — Agent / Workflow

**做什么**：把 AI 接进一条可重复的业务流程，含人工审批环节。

**典型用例**：LINE 客户助手、预订支持、多语客服、内部知识助手、
营销工作流、文档处理流、会议→任务→跟进。

**交付物**：L1 的全部 + 方案架构、Agent 设计、集成规格、
模型与 API 配置、UAT 用例、运维手册

**工期**：3–6 周

**该卖给**：Readiness ≥18 分，且有一条真正高频的流程。

### L3 — Integrated System

**做什么**：接 CRM / ERP / 数据库 / 内部知识库 / 企业 API / 认证系统 / 本地 AI 基础设施。

**交付物**：L2 的全部 + 权限设计、数据处理规则、管理员手册、用户手册、
交接培训、Before/After 度量

**工期**：6 周以上

**该卖给**：有 IT 能力、有系统可接的组织。

### 三档共同的「明确不该卖」

- ❌ **没有 Before/After 基线就开工** → 交付时无法证明价值，
  客户下一年不会续。基线必须在实施前测
- ❌ 客户要求「全自动、不要人工审批」→ 见 `architecture.md` 边界五。
  可以谈，但不能默认开
- ❌ **Readiness ≤10 分还硬上 L2/L3** → 一定失败。
  照实说「你们现在还不该做这个」

---

## 4. Operate — Managed AI

**做什么**：模型接入与路由、用量监控、成本控制、Skill/Agent 更新、
工作流维护、员工 onboarding、故障支持、月度优化、备份与配置管理、治理支持。

**周期**：按月

**为什么它重要**：实施完成不是结束——提示词会变、模型会变、API 会变、
工作流会变、员工会离职、Skill 会失效、Agent 会出错。
**没有 Operate，第一次实施的价值会在半年内衰减掉。**

**这是 ARR 的来源。**

**什么情况下该卖**：**默认跟在每个 Implementation 后面**，作为方案的一部分提出，
不是事后追加。

**什么情况下明确不该卖**：
- ❌ 只做过 L1 Skill Pack 且客户 IT 能力强 → 他们自己能维护，
  硬卖运维会显得贪。可以卖更轻的「季度复查」
- ❌ 客户明确要自己掌控 → 卖 DIY 支持，别抢

## 阶段之间的关系

```
AI Readiness Call（免费）
        ↓
    Discovery ←──────────┐
        ↓                │
    Enablement           │
        ↓                │
   Implementation        │
        ↓                │
    Managed AI           │
        ↓                │
    Expansion ───────────┘
```

**小组织可以在任何一个阶段停下。** 这不是失败——
Discovery 做完客户说「我们自己试试」，也是一次成功的交付。
他半年后回来的概率，远高于被硬推着买了不需要的东西的客户。
