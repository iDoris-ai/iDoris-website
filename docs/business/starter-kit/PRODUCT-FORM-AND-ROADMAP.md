## 0. 先摆一个架构事实

看一眼我们已经写出来的东西的函数签名：

```python
extract(ir, schema, model_output)       # 模型给原始条目，我们解析并校验
translate(ir, target_lang, model_output) # 模型翻译，我们核专有名词与敬语
answer(question, retrieved, model_output) # 模型组织语言，我们判能不能发
assemble(req, model_output)              # 模型写文案，我们卡字数与禁止项
merge(parts)                             # **我们做，不交给模型**
```

**没有一个函数自己调模型。** 它们全都把 `model_output` 当参数收进来。

所以我们已经建成的东西，**既不是 agent，也不是 skill —— 是一层校验（harness）**。
模型提议，我们的代码裁决。

这不是事后总结，是每个模块开头都写着的分工表。**它就是我们的产品。**

## 1. 形态：不是「skill 还是 agent」，是三层

问「我们是 skill 还是 agent」会问不出答案，因为答案是**两个都要，但它们不是一回事**：

```
┌─ 界面层 ── LINE（泰国）· 我们托管的后台（内部）
│            **不做 Web 前端** —— dev-plan 已定
│
├─ 技能层 ── Skill（Markdown）：领域指令、话术、schema、客户的例子
│            **每个客户不一样，改得快，客户看得懂**
│
└─ 校验层 ── Harness（Python）：不可破规则、闸门、审计、路由
             **每个客户一样，改得慢，客户不需要看懂**
```

### 为什么不能只做 Skill

**Skill 强制不了任何东西。** 一份 Markdown 指令能被模型忽略、被后续对话覆盖、
被一句「忽略上面的规则」绕过。

而我们全部的价值恰恰是「规则一定会执行」——
`sensitivity=high` 强制走本地、审批不能跳过、答案没出处不许发、
数字对不上原文就拒绝整份。**这些写进 Markdown 就等于没写。**

> Anthropic 的 `commerce-agents` 把这件事说得比我们清楚：
> **「prompts work only when models comply; code always works.」**

### 为什么不能只做 Agent

一个「有界面的 agent」听起来完整，但：

- `dev-plan.md` 已定 **前端不做** —— 「做前端是最容易看起来很忙但不产生客户价值的事」
- Open WebUI 因 >50 用户的品牌条款排除
- **在泰国，客户的生意发生在 LINE 里** —— 我们做一个网页给谁用？

### 所以形态是：**Harness 托管 Skill，出口是 LINE**

| 层 | 谁写 | 改动频率 | 客户看得到吗 |
|:---|:---|:---|:---|
| Skill（Markdown） | PM + 客户一起 | **每周** | **看得到，也该看** |
| Harness（Python） | Dev | 每月 | 不需要看懂，但可以审计 |
| 界面 | 不自己做 | — | LINE / 客户已有系统 |

**这个三层结构不是我们发明的**，Anthropic 的参考架构是同一套
（skills 按需装载进上下文，核心安全规则永远在 harness 层）——
[评估见此](../eval-anthropic-commerce-agents.md)。**独立走到同一个答案，是个好信号。**

## 2. 一句话说清我们卖什么

> **我们卖的不是「一个 AI 助手」，是「一套让 AI 不能乱来的护栏，外加装在护栏里的领域技能」。**

护栏可复用（所以我们做得起第二个客户），技能按客户定制（所以它真的有用）。

**这句话可以直接给 BD 用。** 客户问「你们和别家有什么不一样」时，
别家答「我们模型更好/更懂行业」，我们答「我们能给你看代码里那条规则，
以及证明它真的会拦的测试」。

## 3. 四个产品的里程碑

### 共同的完成判据（每个里程碑都适用）

一个里程碑只有同时满足这四条才算完成：

1. **不可破规则写成代码**，不是提示词
2. **每条规则配一条变异测试**，且验证过「破坏它，测试真的变红」
3. **两头都有对照**：坏的会红 · 好的不会误报
4. **README 写清它管到哪为止** —— 让人以为「有这个就安全了」比没有更危险

## 5. 我们不做什么（写下来防止范围蔓延）

| 不做 | 理由 |
|:---|:---|
| **Web 前端** | 做前端是最容易看起来很忙但不产生客户价值的事。客户的生意在 LINE 里 |
| **把 Skill 当护栏** | Markdown 强制不了任何东西 |
| **让模型自己合并/自己判断能不能发** | 那等于让它决定「哪条决议可以省略」 |
| **在真模型接通之前继续加动作** | 五个动作都没连过真模型，第六个不会让情况变好 |
| **说话人分离（第一版）** | 权重许可 + 多人会议准确率不稳定 |
