# Creative 组件设计

> Starter Kit 四组件之一。**License 风险最高的一个**，边界必须先说清楚。
> 版本：v0.1 · 2026-09-05

## 0. 先说 GPL 边界（这条比功能重要）

**ComfyUI 是 GPL-3.0。** 它只能作为**独立进程、通过 HTTP 调用**。

具体到可执行的规矩：

- ❌ 我们的仓库里**不含任何 ComfyUI 代码**（不 vendor、不 fork 进来、不复制片段）
- ❌ 不与它静态或动态链接（不 `import comfy`）
- ❌ 不把它打进我们的容器镜像作为同一进程
- ✅ 它作为独立服务部署，我们通过它的 HTTP API 调用
- ✅ 我们的 workflow JSON（描述用哪些节点怎么连）**是数据不是代码**，可以自有

**越过这条线的后果**：整个 iDoris Core 会被 GPL-3.0 传染，
意味着我们所有商业交付的代码都必须开源。这是**不可逆的**——
一旦发行过一次，覆水难收。

> 这条是 `../../agent/architecture.md` 的不可破边界第一条。
> **任何 PR 引入 `import comfy` 或把 ComfyUI 代码复制进仓库，一律拒绝合并。**

**替代路径（如果 GPL 隔离在客户环境里不可行）**：
改用 Gateway 调云端图像模型（各家的图像 API），失去本地化与成本优势，
但完全无 License 风险。这个降级选项要在方案架构里显式写出，由客户选。

## 1. 它到底是个什么东西

**四个具体动作**：

| 动作 | 输入 | 输出 | 典型客户场景 |
|:---|:---|:---|:---|
| **social-pack** | 产品/活动描述 + 品牌配置 | 3 张不同尺寸的社媒图 + 泰英双语文案 | 餐厅出新菜，要发 FB/IG/LINE |
| **adapt** | 一张已有图 + 目标尺寸列表 | 各尺寸的重新构图版本 | 一张主视觉铺到五个渠道 |
| **copy** | 产品信息 + 目标受众/语气 | 泰英双语营销文案（3 个变体） | 促销文案，中英泰都要 |
| **deck-assets** | 演示大纲 | 配图 + 版式建议 | 提案演示的视觉素材 |

**注意 `copy` 不经过 ComfyUI**，它只走 Gateway 的文本模型。
四个动作里只有 `social-pack`、`adapt`、`deck-assets` 涉及图像生成。

### 边界：它不是什么

- **不是设计工具。** 不做编辑器、不做图层。输出是成品图，客户拿去用或让设计师改。
- **不承诺品牌级视觉质量。** 定位是「比员工自己用手机 App 拼的好，
  比专业设计师差」。**这句话要对客户直说**，避免预期错位。
- **不做视频。** 第一版明确不碰。

## 2. 开源基座

| 组件 | License | 它负责哪一段 | 部署方式 |
|:---|:---|:---|:---|
| **ComfyUI** | **GPL-3.0** ⚠️ | 图像生成工作流执行 | **独立进程，HTTP 调用** |
| 图像模型权重 | 各自不同 ⚠️ | 实际生成 | 随 ComfyUI 部署 |
| **iDoris Gateway** | Apache 2.0 / MIT | 文案生成、路由、成本审计 | 我们的服务 |
| **Pillow** | MIT-CMU | 尺寸裁切、文字叠加、格式转换 | 我们的进程内 |

> ⚠️ **模型权重的 License 是独立于 ComfyUI 的另一个风险面。**
> 常见的开源图像模型权重各有各的许可（有的禁商用，有的要署名，
> 有的对生成内容有限制）。**[待核：逐个确认我们要用的每个权重的许可，
> 特别是商用条款]** —— 见 [`../oss-due-diligence.md`](../oss-due-diligence.md)。
> **在这条核清楚之前，Creative 不对外交付。**

## 3. 我们自己写什么

### 3.1 品牌配置（BrandKit）

这是 Creative 唯一真正的差异化——**让输出看起来像这家客户的东西**：

```jsonc
{
  "brand_id": "hotel-xxx",
  "palette": {"primary": "#...", "secondary": "#...", "text": "#..."},
  "fonts": {"th": "Sarabun", "en": "Inter"},   // 泰文字体是硬需求
  "logo": {"asset_id": "...", "safe_area_pct": 8},
  "tone": {"th": "สุภาพ เป็นกันเอง", "en": "warm, concise"},
  "forbidden": ["不得出现人物面部", "不得使用竞品配色"]
}
```

**泰文字体是必须的**：多数图像/排版流程默认字体不含泰文字形，
直接出方框。这是本地化的具体内容之一，不是锦上添花。

### 3.2 尺寸预设表

```
facebook_post   1200x630     line_oa_rich    1040x1040
instagram_post  1080x1080    line_oa_card    800x800
instagram_story 1080x1920    print_a5        1748x2480 @300dpi
```

LINE 的两个尺寸单列，因为**泰国市场 LINE 比 FB/IG 更重要**
（[待核：LINE 泰国用户规模，见 `../thailand-channels.md`]）。

### 3.3 Workflow JSON

描述「用哪些 ComfyUI 节点、怎么连、参数是什么」。**这是数据不是代码**，
所以可以是我们的自有资产，不受 GPL 传染。

### 3.4 后处理

Pillow 做：按预设裁切、叠加 logo（守 safe area）、叠加泰英文案、导出。
**文字叠加放在我们这边而不是让模型生成文字**——图像模型生成的文字，
尤其是泰文，基本不可用。

## 4. 接口

```
POST /creative/social-pack
  body: { brand_id, subject, channels: ["facebook_post", "line_oa_rich"], lang: ["th","en"] }
  → { assets: [{channel, url, w, h}], copy: {th: [...], en: [...]}, usage: {...} }
```

```
我们的服务 ──HTTP──> ComfyUI（独立进程，GPL 隔离）
     │
     ├──> Gateway ──> 文本模型（文案）
     └──> Pillow（裁切/叠字/导出，进程内）
```

## 5. 最小可用形态

**先做 `social-pack` 一个动作，且只支持两个渠道**（`line_oa_rich` + `facebook_post`）。

理由：
- 它是四个里**唯一能独立产生客户价值**的（其余三个都是它的变体或补充）
- 两个渠道足够演示「一次输入、多渠道输出」这个卖点
- **`copy` 可以先独立上线**——它不碰 ComfyUI，没有 GPL 与权重许可风险，
  可以在图像部分还在尽调时先交付

> **策略性建议**：如果 [待核] 的权重许可迟迟核不清，
> **先只上 `copy`**（纯文案，零 License 风险），图像部分推迟。
> 泰英双语营销文案本身就是一个能卖的东西。

## 6. 怎么演示给客户看

1. 让客户描述一个**他们真的要发的**东西（新菜品 / 促销 / 活动）。
2. 用他们的 logo 和配色（现场填 BrandKit）。
3. 出 LINE 和 FB 两个尺寸 + 泰英文案各 3 个变体。
4. **主动说**：「这个水平大概是能直接发的 70%，剩下 30% 你们的设计师
   花 10 分钟能调好——比从零做省 2 小时。」
5. 说明这次花了多少钱。

第 4 步的诚实定位比多演示两张图重要。**把 Creative 说成能替代设计师，
第一个客户就会退货。**

## 7. 风险

| 风险 | 影响 | 对策 |
|:---|:---|:---|
| **GPL 传染** | **不可逆，全部代码被迫开源** | 独立进程 + 代码评审硬拒绝 `import comfy` |
| **模型权重商用许可不明** | 客户使用产出物可能侵权 | **[待核] 核清前不对外交付**；可先只上 `copy` |
| 泰文字形缺失 | 出方框，演示翻车 | BrandKit 强制指定泰文字体；预跑检查 |
| 客户预期是「替代设计师」 | 退货 | 演示第 4 步的定位话术写死 |
| ComfyUI 部署运维成本 | GPU 资源 + 版本维护 | 第一批客户用我们托管的共享实例，不给客户自部署 |
