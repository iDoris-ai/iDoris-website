# 泰国渠道路径

> depa 合作 / Digital Catalog 注册 / 注册培训课程，三条路径的门槛与顺序。
> **本文档几乎全部是 [待核]。** 集中清单见 [`facts-to-verify.md`](facts-to-verify.md)。
> 版本：v0.1 · 2026-09-05

## 0. 先说这份文档的可信度

**下面所有关于泰国政府流程、金额、日期、人名的内容，
来源都是 `iDoris_AI_Thailand_Local_Service.md`（2026-09-04），

政府流程比模型价格更容易过期，也更贵——

所以：**这份文档可以用来规划顺序，不能用来做承诺。**
任何对外沟通（提案、一页纸、与 depa 的对话）中引用这些数字之前，
必须先核。

## 1. 总策略

> **先成为 depa 认识并愿意合作的人 → 再成为 depa 项目的合作伙伴 →
> 再成为 Registered Training Provider → 最后把产品放进 Thailand Digital Catalog。**

**而不是**：注册公司 → 认证 → 等半年 → 然后才第一次去见 depa。

**为什么**：前一条路线在准备资质的同时已经有客户、有案例、有当地关系；
到正式申请 Catalog 时**已经在圈子里面**。

## 2. 路径 A · 与 depa 建立关系（最先做，成本最低）

### 做什么

去清迈的 depa Upper Northern Branch，**不是去要补贴**，是去说：

> "I am building an open-source AI adoption framework for Thai SMEs and
> educational organizations. We already have working Thai AI tools and would
> like to contribute as a local implementation and training partner."

带三样东西：① 一页纸（[`one-pager-en.md`](one-pager-en.md)）
② 一个能现场演示的东西 ③ [`sample-discovery-hotel/`](sample-discovery-hotel/)

**第三样最重要**：它让对方立刻明白「这个人不是来讲大模型的，
是可以带 SME 做转型的」。

### 前置条件

- ✅ 一页纸 —— **已有**
- ✅ Discovery 样例 —— **已有**
- ⚠️ 能现场演示的东西 —— **待做**（Starter Kit 最小形态）

### 成本

时间：一次拜访 + 后续跟进。金钱：**零**。

### 我们现在缺什么

**只缺一个能演示的东西。** 见 `dev-plan.md` 阶段 B。

### [待核] 事项

| 断言 | 怎么核 |
|:---|:---|
| depa Upper Northern Branch 在清迈，地址 158 Thung Hotel Road, Wat Ket | depa 官网 get-in-touch 页 |
| 现任 Branch Manager 姓名 | 同上。**人事会变，见面前当天再核一次** |
| depa 有 Digital Provider / dSURE 注册体系 | depa 官网 |

> ⚠️ **人名尤其要当天核。** 拿着过期的人名去拜访，第一印象就毁了。

## 3. 路径 B · 与已在 Catalog 的 Digital Provider 联合交付

### 做什么

找 2–3 家已在 Thailand Digital Catalog 的清迈/曼谷 Digital Provider，
**做真实的联合交付**：

| 我们负责 | 对方负责 |
|:---|:---|
| Discovery | 泰国合同主体 |
| AI Enablement | 已有的 Catalog 产品 |
| AI Skills / Agents | 政府 / depa 流程 |
| 开源 AI 集成 | 本地客户渠道 |

### 为什么第一年很值得

不是为了钱，是为了**学会规则**：depa 怎么买东西、SME 怎么拿补贴、
TOR 怎么写、Digital Provider 怎么报价、政府怎么验收。

**这些经验比关起门研究法规值钱得多。**

### ⚠️ 一条红线

**必须是真实的联合交付 / 分包 / 共同方案，不能名义挂靠。**

[待核] 源文档称最新版规则对「经销商」的明确通道主要针对 Cloud Technology，
**普通软件不能简单借别人的 Digital Provider 身份把自己挂进去**。

**核之前不能做什么**：不得与任何 Provider 达成「借资质」性质的安排。

### [待核] 事项

| 断言 | 怎么核 |
|:---|:---|
| Thailand Digital Catalog 有大量本地 Provider | Catalog 网站 |
| 经销商通道主要针对 Cloud Technology | depa 最新版注册规则文件 |
| 通过 Catalog 产品可获政府采购 / Transformation Voucher 机会 | depa 官网 |

## 4. 路径 C · 注册 Digital Course（可与 B 并行）

### 做什么

[待核] depa 有独立的 **Digital Skill Roadmap — Registered Digital Courses**，
可注册 Digital Skill for All / Digital-driven Career / Digital Professional 三类。

我们要注册的课程：

> ### iDoris Practical AI for Workplace
> **From Chat → Skill → Workflow → Agent**

**不是教 Prompt**，而是教员工怎么把 AI 放进每天真实的工作。
这与我们的 Enable 服务天然匹配。

### 为什么值得

**Training 不是主要盈利业务，而是获客渠道。**

```
depa Registered Training → 发现企业需求 → Discovery Sprint
    → Starter Kit → Implementation → Managed AI
```

### 前置条件（全部 [待核]）

- 泰国法人 + VAT
- 课程内容
- 培训人员资质
- 培训平台
- 已出售课程的证明

### 我们现在缺什么

**缺泰国法人与 VAT。** 这是路径 C 和 D 的共同前置。

## 5. 路径 D · 自己进 Thailand Digital Catalog（最后做）

### 顺序

```
2 个真实收费客户 → 泰国公司 → VAT → 产品化
→ ISO/IEC 29110 或 CMMI → Thailand Digital Catalog
→ depa 项目 / 政府 / SME 采购渠道
```

### ⚠️ 关键：先做两个真实收费客户

[待核] 源文档称注册要求提供：
- **至少 2 张来自不同客户的销售 Tax Invoice**
- 至少 1 份客户工作/成果证明
- 产品手册、功能说明、价格、售后流程、投诉处理、产品开发流程

> **depa 自己在说：不要注册一个 PPT 产品。先卖出去，再来。**

**这直接决定了我们的排期**：M1「明天能开业」排在产品开发之前，
不是保守，是**政府渠道的硬性前置**。

### ISO/IEC 29110

[待核] dSURE Software 类目接受的基础标准包括 ISO/IEC 29110 或 CMMI。
对我们这个规模，**优先研究 29110**，不要上来搞 CMMI。

**现在就该做的一件事**（不花钱）：开发流程按
`Requirement → Design → Development → Review → Test → Release → Change Management`
留下规范记录。

**我们其实已经在做了**：pilot 的 plan → tasks → PR → review → merge 流程
本身就接近这个形状。**这不只是为了认证，它本身就该是工程标准。**

### [待核] 事项

| 断言 | 影响 | 怎么核 |
|:---|:---|:---|
| 注册费约 500 THB/产品组/年 | 预算 | depa Catalog 收费说明 |
| 每月 1–14 日受理，次月底公布 | 排期 | 同上 |
| 需 ≥2 张不同客户税务发票 | ~~整个 M1 的排期依据~~ **依据存疑** | **2026-09-06 核过：Provider 准则公告已于 2024-09-12 撤销；Catalog 页必备文件里无发票；两者可能是不同的门。见 [`verification-2026-09-06-depa-channel.md`](verification-2026-09-06-depa-channel.md)** |
| 基础标准含 ISO/IEC 29110 | 认证方向 | dSURE 标准清单 |
| 数据/云基础设施须在泰国，过渡放宽至 2029-02-15 | 架构决策 | 最新版规则 |

> **最后一条如果为真，我们现在有时间先跑业务再设计本地基础设施。
> 如果为假，架构要提前考虑泰国境内部署。这条的影响最大。**
