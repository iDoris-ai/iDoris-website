# 03 · AI Readiness 评分

> 虚构样例。判据见 [`../discovery-skill/templates/readiness-score.md`](../discovery-skill/templates/readiness-score.md)

| 维度 | 分 | 现场依据 |
|:---|:---:|:---|
| **数据可得性** | 2 | LINE 可导出、PMS 能导 CSV；但交班记录是**纸质本子**，菜单散在个人电脑 |
| **流程标准化** | 2 | 有惯例无成文。前台三个人回 LINE 的措辞各不相同 |
| **工具基础** | 2 | LINE OA / PMS / Canva / Excel 各自独立，**互不打通**；[待核] PMS 无可用 API |
| **人员意愿** | 4 | 前台已自己在用 Google 翻译；老板试过 ChatGPT；**无人表达抵触** |
| **治理准备** | 3 | 老板对「答错房价谁负责」有明确意识，但**无成文数据规矩** |
| **总分** | **13 / 25** | |

## 结论

**13 分 → 落在 11–17 区间 → 从 L1 Skill Pack 起步，不要一上来做集成。**

**最弱维度：数据可得性与流程标准化（各 2 分）与工具基础（2 分）。**

这三项都低，意味着：
- ❌ **不适合做 L3 集成**——没有可接的 API，接了也没有结构化数据可用
- ✅ **适合做「不依赖系统集成」的用例**——翻译、文案、回复草稿都不需要接 PMS

**「人员意愿」4 分是这家客户最大的资产。** 前台已经自己在用工具了，
说明推行阻力小——这比技术基础重要得多。

## 一条明确的建议

**治理准备只有 3 分，但老板已经问了对的问题**（「答错房价谁负责」）。
建议在实施前先做一件不花钱的事：**把「哪些回复必须人工确认」写成一页纸的规矩**。
这比任何技术措施都有效。
