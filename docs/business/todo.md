### ✅ 已决：`budget.scope = paid_only`（不是 `all`）

契约 §4 对我们原本那条「预算用尽必须拒绝」做了细化，**并把选择留给我们**：

- `paid_only`：只闸 `cost > 0` 的候选，**零成本的本地模型照常可用**
- `all`：一律拒绝（我们原本的行为）

**选 `paid_only`，理由是具体的**：`policy.example.json` 里
`line.reply`（面向客人的 LINE 回复）**本来就走 `local`**，因为含客人信息。

| | 老板的月度预算烧完之后 |
|:---|:---|
| `paid_only` | LINE 回复**照常工作**；停的是文档翻译/对比这类内部批处理 |
| `all` | **连客人发消息都没人回** |

对清迈的小生意，第二种是不可接受的 —— 而第一种停掉的东西**看得见、可以等到下次充值**。

> ⚠️ **前提：402 必须传到人 —— 这条归属明确在我们这层。**
>
> 内部功能悄悄停掉而没人知道为什么，和悄悄花钱是**同一类错误的两面**。
>
> **为什么是我们做**：Router 能做的到 `X-iDoris-Reason` + 402 结构化错误体为止；
> 再往前一步就要知道「**谁是老板、他用什么看通知**」—— 那是业务语义，
> 契约明确不承载。我们做界面，所以在我们这儿。
> （iDoris 侧会在契约的「未定/后续」里写明归属，
> **免得以后有人以为两边都没做是漏了**。）
>
> **验收**：预算耗尽 → 老板在他实际会看的地方（LINE / 后台）收到一条通知，
> 说清「是预算不是故障」。没有这条通知就不算做完 ——
> 一个只写进日志的 402 等于没传到人。

### ⚠️ 开账单前必须断言 `range_utc`（契约 v1.1 给的凭据）

契约 v1.1 把「月份边界按租户时区」从**一句声明**改成了**可验证的字段**。
`usage` 响应现在必带：

```json
{ "period": "2026-09",
  "billing_timezone": "Asia/Bangkok",
  "range_utc": {"from": "2026-08-31T17:00:00Z", "to": "2026-09-30T17:00:00Z"} }
```

**为什么这个改动要紧**：原来只有一句「我们按租户时区切月」——
我们只能信。**真错了，跟我们自己踩过的那个 bug 一样，不会有任何东西报错。**

**所以我们这边的验收是**：开客户账单**之前**，断言 `range_utc.from/to`
等于「该 `billing_timezone` 下该月的首末时刻」。对不上就拒绝出账单，
**不是记个日志继续出**。

契约同时明确：**不接受调用方在查询里另指定时区** ——
否则同一租户的两个调用方能切出不同的月，比服务器时区更糟。

### ⚠️ T-0 完成时必须带上这条验收（现在记，免得到时候补不上）

**「敏感任务没出站」不能只断言路由决策。**

我们现在的测试断言的是 `d.tier == "local"` —— 那是**决策**。
今天没问题（`route()` 只做决策不调用），但**接上真实调用之后就不够了**。

iDoris 侧的 `test:privacy` 点明了为什么：

> 只断言「返回了 503」是不够的 —— **「先转出去、拿到结果、再因为别的原因返 503」
> 同样是 503**。计数器才是真正证明没出站的那个断言。

**T-0 的验收必须是**：停掉全部本地 provider → 发 N 条 `sensitivity=high`
→ 断言 N 条全部失败 **且假上游的出站计数器 == 0**。

**两个断言缺一不可**：只有前半条，一个「先出站再失败」的实现同样能通过。

这和本仓库反复抓的是同一件事：**断言因为错误的原因通过**
（`compare` 的重复配对被覆盖对账接住、`search` 的无出处答案被数字校验接住、
`check-letters` 的剥注释因为下限都是「至少」而不承重）。
