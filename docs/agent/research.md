## 五步框架

### 1. 要解决的问题

泰国的中小企业、教育机构和本地服务业**不缺 AI 演示，缺的是「AI 进到我每天的活里」**。
他们真正需要回答的是五个问题：

- 今天哪里用 AI 能产生可度量的价值？
- 哪些流程该保持不动、哪些可以加速？
- 什么时候该用简单工具、什么时候该用可复用 Skill、什么时候才需要 Agent？
- 成本、隐私、权限、模型选择怎么控制？
- 上线之后怎么保证它继续能用？

痛点的主人是**组织的运营负责人**，不是 IT。他衡量的是「提案从 120 分钟降到 25 分钟」，
不是「我们用上了 RAG」。

### 2. 现有方案全景

| 方案 | 能力 | 可借鉴 | License |
|:---|:---|:---|:---|
| Dify | 可视化 Agent/工作流编排、知识库、多模型接入 | 工作流编排模型、知识库分块策略 | 改版 Apache 2.0，**明文禁止多租户**（[已核] 2026-09-05）→ 排除 |
| n8n | 通用自动化编排、400+ 连接器、可自托管 | 连接器抽象、触发器模型 | Sustainable Use License（**非 OSI 开源**，商用托管受限） |

| Whisper / faster-whisper | 语音转文字，含泰语 | Voice 模块基座 | MIT / MIT |

**结论**：底层能力**基本都有成熟开源件**，不需要从零造 Agent 运行时、模型网关、
文档解析或向量库。

### 3. 差异化立足点

上表里没有任何一个解决「**泰国某家清迈酒店明天早上怎么少干两小时**」。
它们全是**工具**，而客户缺的是**从发现到运维的一条通路**。

我们的结构性空白有三处：

1. **Discovery 是可复用资产，不是咨询工时。**
   把「进一家企业、盘出该用 AI 的地方、给出 90 天路线」固化成一个开源 Skill，
   任何一个 FDE 按同一套流程都能做出同质量的交付物。市面上没有开源的 AI 采纳
   Discovery 方法论 + 可执行工具。
2. **本地化不是翻译，是渠道与信任。**
   泰语 native 的项目经理 + 教育系统的天然分发 + 政府数字化生态，
   这三样外来技术团队买不到。
3. **开源与商业的边界画在「便利」上，不画在「功能」上。**
   DIY 免费且真能用；付费买的是省时间、担责任、上规模。这让开源版本不必被
   故意做残，因而真的会有人用，因而才有飞轮。

### 4. 可复用 vs 要自建

> **本节的 License 结论已由 [`../business/oss-due-diligence.md`](../business/oss-due-diligence.md)
> 逐条核实（2026-09-05），并纠正了本文件此前的两处错误（LiteLLM、Dify）。
> 上表中标 [已核] 的以尽调文档为准。**

**站在巨人肩上（不自建）**
- 模型路由与成本控制 → LiteLLM
- Agent 状态机与人工审批 → LangGraph
- 语音转写 → faster-whisper
- 文档解析 → Docling
- 向量检索 → pgvector（先不上独立向量库，一个 Postgres 够用到很久）
- 图像生成 → ComfyUI（**独立服务，GPL 隔离**）

**必须自建（这是我们的资产）**
- **iDoris Discovery Skill** — 访谈脚本、工作流地图模板、AI Readiness 评分、
  Impact×Effort×Risk 矩阵、90 天路线图生成。这是差异化的核心。
- **Role-Based Skill Pack 规格与模板** — 让「培训」的产出是可复用资产而不是 PPT。
- **交付流程本身** — 三角色分工、阶段门、交付物清单、Before/After 度量方法。
- **泰国本地化层** — 泰语提示词、LINE 通道、泰文文档解析的坑、本地合规话术。

### 5. License / 合规边界

**红线（写死，任何人不得越过）**
- **GPL-3.0 组件（ComfyUI）只能作为独立进程/服务调用**，绝不静态链接、绝不
  把其代码并入我们的发行物。越过这条线，整个 iDoris Core 会被传染成 GPL。
- **n8n 是 Sustainable Use License，不是开源**。可以自用，**不可作为我们托管
  服务的核心卖点**转售。若需要通用连接器编排，优先自建轻量层或换 Apache 2.0 方案。
- **Dify 明文禁止多租户**（[已核]）——我们的托管模式按其定义就是多租户，**已排除**。
- **Open WebUI** 在 30 天滚动周期内终端用户 >50 时不得移除其品牌标识（[已核]）。
- **LiteLLM 的 `enterprise/` 目录另有许可**（[已核]）——只用核心，绝不引用该目录。
- 我们自己的开源部分统一 **Apache 2.0**（与官网页脚已公示的一致）。

**数据边界**
- 客户的数据、内部流程、业务逻辑**永不进入开源仓库**，也不进入我们的公共样例。
- 可以开源的是：连接器、Skill、Agent 模式、评测方法、工作流模板、工具。
- Discovery 产出的样例一律使用**虚构的酒店/学校**，不使用真实客户信息。

## 结构性空白（差异化）

一句话：**没有人把「AI 采纳的方法论」做成开源资产，并用本地交付去反哺它。**

工具是红海，方法论是空白。而方法论恰恰是这门生意里唯一能被复制、被开源、
被政府渠道认可的东西。

## 结论

**做，从 Discovery 切入。**

第一个里程碑不指向「做出产品」，指向「**让这门生意可以被卖出去**」——
服务定义清楚、价格标出来、有一个能演示的样例、有一条任何 BD 都能照着走的路径。

产品（Starter Kit / Gateway / LINE Agent）是第二里程碑的事。
先卖出去两个真实收费客户，比先做完产品重要——这既是商业常识，
也是 [待核] depa 注册材料的硬性要求。
