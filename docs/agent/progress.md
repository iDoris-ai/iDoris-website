## 本轮最重要的三个发现

### 1. 开源尽调推翻了两条我们此前凭印象写下的结论

- **LiteLLM 不是纯 MIT** — `enterprise/` 目录另有许可。它是 Gateway 基座，
  所以成了硬约束：绝不引用该目录，每次升级检查功能有没有被挪进去。
- **Dify 不是「须逐条读」而是明文禁止多租户** — 我们托管多客户就是多租户。
  排除它是对的，但此前给的理由不准。

**GitHub 对这两个仓库都返回 `NOASSERTION`——这个信号本身就说明许可不标准。**

### 2. 一个阻塞级技术风险

**LangGraph 经 `langchain-core` 传递依赖 `langsmith`，包一定会被装上。**
[待核] 必须在断网容器里抓包确认零出网。客户的会议内容是最敏感的数据，
「大概不会上传」不是可接受的答案。核清之前 Assistant 不得进任何客户环境。

### 3. 模型权重的许可独立于代码

图像生成模型、Whisper 权重、Docling 的 OCR 模型，三者许可全部 [待核]。
**代码 MIT 不代表权重可商用。** 降级路径已写死：Creative 先只上纯文案的 `copy`。

### 冲突是什么

`/goal` 正文写：

> 仓库主人已授权自审自合。**自审通过就合并进 preview 并 safe-cleanup。**

`/goal` 末尾追加写：

> 另外我授权你如果上面任务都完成了，我还没叫停，你就开始把上边的产品的规划开始做开发。
> 对，那**开发之后呢，PR 自己不要 review。或者说自己不要合并，可以 review 不断的提 PR。**

停止条件里有一条是「**无未合并的 open PR**」。

**这三句放在一起，是自相矛盾的**：要满足停止条件就必须合并，
而追加那句明确说开发阶段的 PR 不要自己合并。
