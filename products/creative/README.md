# iDoris Creative — copy 动作（泰英双语营销文案）

> 设计见 [`../../docs/business/starter-kit/creative.md`](../../docs/business/starter-kit/creative.md)
> 状态：**`copy` 已完成**。`social-pack` / `adapt` / `deck-assets` 三个动作**被 License 阻塞**。

## 为什么先做这一个（而且只做这一个）

Creative 的其余三个动作都要经 **ComfyUI**，而：

1. **ComfyUI 是 GPL-3.0** —— 只能独立进程 HTTP 调用（见 `creative.md` §0）
2. **[待核] 图像模型权重的商用许可还没核清** —— 代码 MIT 不代表权重可商用

`copy` **不碰 ComfyUI**，只走 Gateway 的文本模型：

> **零 GPL 风险 · 零权重许可风险 · 可以先交付**

而且**泰英双语营销文案本身就是能卖的东西**——不是「等图像做好了才有价值」的半成品。
这正是 `creative.md` §5 写死的降级路径。

## 三条硬要求

**① 渠道字数上限是硬闸，不是建议。**
LINE OA 的推送被截断、Instagram 的说明被折叠——**客户看到的是残缺的文案**。
超限直接拒绝，让人改，而不是发出去再说。

不同渠道用**各自的**上限，不是一刀切。**未知渠道直接拒绝，不猜**——
猜错的后果同上。

**② `BrandKit.forbidden` 是禁止项，逐条校验，大小写不敏感。**
「不得出现竞品名」「不得承诺具体折扣」这类约束，**客户提出来就是因为踩过坑**。
模型不会记得，我们必须查。大小写不敏感是因为改个大小写就能绕过去。

**③ 泰文敬语跨变体一致。**
与 Documents 的 `translate` **同一套判定**。同一家客户的翻译和文案如果一个用
`ครับ` 一个用 `ค่ะ`，**比两个都用错更糟**——那看起来像两个人在冒充同一个品牌。

单条看不出问题，**一组放在一起才看得出**，所以检查是跨变体做的。

## 模型做什么、不做什么

**做**：写文案。
**不做**：判断有没有超字数、有没有踩禁止项、敬语一致不一致。

## 怎么跑

```bash
python3 copywriting.py       # 烟测
python3 test_copywriting.py  # 完整测试（10 个测试函数）
./mutation_check.sh          # 变异测试（11 条）
```

## 每条硬要求都配了负对照

| 正向 | 负对照 |
|---|---|
| 超限被拒 | **恰好等于上限**必须放行 |
| 未知渠道被拒 | **每个已知渠道**都必须放行 |
| 禁止项被拦（含大小写变体） | 干净文案通过 · **空禁止项列表**时不因此拒绝 |
| 敬语混用被拒 | 统一用一种通过 · **不要泰文时不跑这条检查** |

没有这些负对照，「什么都拒绝」也能让正向断言全绿。

## [待核] 渠道字数上限

`CHANNEL_LIMITS` 里的值**需要定期核**——各平台的限制会变。

**核法**：各平台官方开发者文档。**谁核**：Dev，季度复查。

取值刻意保守：**宁可让人删两个字，不要让客户看到被截断的文案。**
